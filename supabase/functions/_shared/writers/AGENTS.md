- 15 expression sliders + Story Divergence mode live in `supabase/functions/_shared/writers/sliders.ts` (pure, shared); legacy fields (velocity, scope, entityComplexity, perspectiveMultiplexing, emotionalIntensity, divergenceAllowed) are read through it — no data migration needed.
- `books.voice_manifest` is written once, server-side, on first section generation (`_shared/writers/manifest.ts`) and never overwritten.
- Share book-type opening guidance from `_shared/writers/opening.ts` in writing, intro and preview prompts to prevent formulaic openings without changing cache or model roles.
- The anti-procedural craft rule lives in pure `_shared/writers/dramaticAction.ts` (`dramaticActionDirective`), injected into the static writing system prompt for narrative prose types (novel, fiction-serial, short-story, biography, memoir) and empty for formats with their own engines — it bans narrated processes/steps and caps revelations at two sentences.
- Style Diversity layer lives in `_shared/writers/rhetoric.ts` (pure) and runs in `generate-content` only for books with a usable progressive plan (Standard prompts stay byte-identical); the opening-strategy ledger is derived from saved section text rather than stored, so regeneration needs no undo, and the strategy goes only in the dynamic prompt tail to keep the cached prefix byte-identical.
- Naturalness Engine contracts live in pure `naturalness.ts`; mode defaults Off (`controls.naturalness`), findings are advisory-only and can never block acceptance, and style adaptations overlay copies — base writer profiles stay immutable.
- Stage C naturalness rewriting lives in pure `naturalnessRewrite.ts`: only in mode "analyze_and_rewrite" (legacy "advise" = analyze_only, never rewrites) or when the author requests `naturalness_rewrite` on a held candidate in `candidate-review` (saves a new candidate version, never accepts), only on the unaccepted draft before `runPreAcceptance`, ≤2 attempts of find/replace edits (dialogue, names, numbers protected, ≤ change limit, no new deterministic findings, strictly better score); any failure keeps the original draft — the result always goes through full validation and fenced acceptance.
- Stage D writer learning lives in pure `learning.ts` (+ best-effort `learningRepo.ts`, owner-only `writer-learning` function): signals come only from stored findings and outcomes, a recommendation needs recurrence (≥3 sections, ≥2 chapters) plus an author-approved or proven signal, detector signals are low-weight and never sufficient, overlays are new versioned rows (never edits to base profiles; slider nudges clamped to ±2), and only active, pinned overlays reach the dynamic prompt tail in `analyze_and_rewrite` mode.
- Paid naturalness A/B experiments run only through pure `_shared/writers/abExperiment.ts`: worst-case cost is reserved before every call (counted input + max output, uncached rates, markup), unpriced models and fallbacks are refused, and all three texts (original, flawed copy, revised) are returned without writing any book data.
- All "how much changed" checks (naturalness rewrite budget, continuity revision ratio) use the word-level diff in pure `_shared/writers/textDiff.ts`, always against the original baseline: unchanged text between separate edits never counts, moved passages count as delete+insert.
- A naturalness rewrite is judged on the whole section, not the replaced text: candidates that introduce a new repeated sentence shape (`repeatedTemplates`), a new stock phrase, in-sentence repetition or flatter rhythm are rejected, and remaining stock phrases/duplicates/shapes are always returned as `unresolved` — a lower score alone never counts as an improvement.
- Rewrite name protection never treats sentence-start capitals as names: names are canon `knownNames`, mid-sentence capitals, or capitals whose lowercase form never appears in the draft.
- Literary rewriting uses its own `literary_reviser` role (pure `literaryReviser.ts` + `literaryReviserServer.ts`), never `editor` (manual paragraph rewrite) or `continuity_reviser` (mechanical repair): per-book `controls.literaryReviser` (mode off/on_request/automatic, default off; model Sol only; per-section cost cap), exact model with the author's own key only (`requireUserKey`), fallback only if configured AND `fallbackAuthorized`, worst case reserved before every call, and results always go through full validation and fenced acceptance.
- Writer Personas live in `supabase/functions/_shared/writers/personas.ts`; the book stores only `controls.writerId` (missing = best fit) and the rendered block sits in the static system prompt — voice survives model changes and stays prompt-cache safe.
- One pipeline for every writer (`PREMIER_PROFILE` in `profiles.ts`, resolved in `ai/roles.ts`): prose drafts on Sonnet 5 unless the book's `controls.draftModel` toggle picks Sol (script formats default to Sol), every other role runs on Sol, and the registry holds only those two models — writer distinctness comes from persona, sliders and tone, never models.
- Try Writer (`try-writer` + /writers) is preview-only: it never writes books, manifests or story memory; DeepSeek thinking is a request parameter derived from the profile slot mode, never a separate model id.
- Both writer preview entry points share one WriterStudio UI (same locked modes and bounded controls); `try-writer` stays preview-only.
- Edit replies go through `parseEditsDetailed` (salvage + stop reasons); truncated/malformed output is an infrastructure outcome, never a quality verdict.
- Tone↔writer harmony lives in pure `_shared/writers/toneMatch.ts`: a tone suggests a writer and nudges sliders only within baseline ±2; Book Variants/concepts/premise rewrites get the selected writer's voice block via `BookBrief.voice` — later planning and Standard prompts are unchanged.
- Writer selection hierarchy is book type → sub-category/genre → tone: `GENRE_SPECIALISTS` in `personas.ts` maps genres to writers (Romance/Literary → Sophia, Sci-Fi/Speculative → Julian, Mystery/Thriller → Marcus, Humor → Ethan), but a specialist only wins when qualified for the book type, and tone only chooses among type-qualified writers.
