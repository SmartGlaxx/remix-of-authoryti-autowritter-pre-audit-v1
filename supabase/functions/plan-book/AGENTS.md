- Phase 4 Book Setup lives in pure `planning/bookSetup.ts` and is stored in `books.story_setup` (server-only via `plan-book` setup_save; a trigger blocks browser writes): it is planner-only guidance merged into the existing master planner, never canon; after prose exists, story/narrator/POV/vantage/universe/identities are locked (only roles, notes, pen name editable) so accepted history can't be silently rewritten.
- Summary length bands by book type live in `planning/aiPlanning.ts` (`summaryBand`, `SERIES_BOOK_BAND`); prompts give the band as guidance and parsers repair only clearly out-of-range output, so lengths stay elastic per type. Series mode is read from `books.controls.series` and stored as `genre_data.series_books` on the master plan.
- Plot-twist mode is chosen at inception (Step 1, `story_setup.twistsEnabled`) and sent as `twistMode` with `alternatives`, so every option is architected around its twist; `adjust_premise` rewrites only the seed idea (fail-closed test mode uses the free mock) and the later twist card only schedules reveals/extra twists for the chosen story.
- Story alternatives, concepts and twists call the book's real planner model for authors (authorized by the user); test mode or `STORY_AI_ENGINE=mock` always uses the deterministic free engine, so tests never reach a paid model.
- Phase 3 character knowledge lives in pure `knowledge.ts` (+ `knowledgeRepo.ts` I/O): extracted only from accepted text and only for books with a universe, narrator identity or progressive pipeline (Standard extraction prompt unchanged); holders resolve to exactly one stable identity or go to `knowledge_identity_reviews`; scene order uses story dates first and undated flashbacks stay "unclear"; protected secret terms are advisory notes and only a definite, verbatim-quoted semantic disclosure, premature knowledge or POV breach (or a narration age/post-death impossibility at a known scene date) blocks — deception, dialogue claims, hindsight devices and uncertain dates never do.
- Recognising a knowledge holder never approves the claim: `knowledgeHold` holds claims from no-longer-accepted text, claims naming a later reveal's secret terms, and "certain" facts backed only by deduction as `knowledge_check` reviews linked to the identity.
- Unmatched knowledge holders are resolved only by the owner via `plan-book` resolve_review: confirm a listed candidate, create a distinct lightweight identity, defer, or dismiss; the held item is re-planned through `planKnowledgeWrites` so the dedup key stays idempotent — never auto-attached.
- AI test mode is fail-closed: `testMode: true` / `x-ai-test-mode: 1` wraps deps in `failClosedDeps` (no user, platform or gateway key reachable; unmocked calls fail `test_mode_blocked` 403), and live harnesses must first match `plan-book` `action: "version"` and abort on mismatch — a stale deployment ignores the flag, so it is never sent an AI-capable request.
- Free end-to-end testing uses the `x-ai-test-mode: 1` header (or `testMode: true`) on `plan-book`, `candidate-review` and `extract-narrative-state`: model replies are caller-supplied or a deterministic mock and go through the real parsers, checks and fenced commits; with no stand-in the call is refused and no key is reachable — live tests can never spend AI credit.
