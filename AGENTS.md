- Narrative engine pure logic lives in `supabase/functions/_shared/narrative/` (rules, context, extraction) and is imported by both edge functions and `src/` — one source of truth for browser, backend and tests.
- Paragraph/dialogue memory lives in pure `sectionMemory.ts`, persisted inside the existing extraction's `applied.sectionMemory`; writing and UI read only completed records whose hashes match current completed prose, before the writing position — avoids a second ledger and stale/future-text leaks.
- Character references use `characterReference.ts` for pure lock/tell rules and the shared OpenAI image service with low quality and no failure fallback; exact biometrics are designed/author values, never claimed as image measurements.
- Story-state extraction runs server-side (`extract-narrative-state`) from the saved section text, idempotent per section via `narrative_extractions` (content hash + undo log) — prevents duplicates and never trusts client prose.
- All AI text calls go through `supabase/functions/_shared/ai/` (registry → `resolveModelForRole` → adapters → `streamAI`/`generateAIText`) — one place for models, pricing, providers, retries, fallbacks and usage records.
- Initial actions use `ai/ideation.ts` call-local config and strict schemas; later planning keeps book routing to protect fixed profiles.
- User provider keys are AES-GCM encrypted server-side (`BYOK_ENCRYPTION_KEY`, per-user HKDF) in `user_provider_keys`, which has no client access — keys are write-only from the browser.
- Books without a `book_model_configs` row use the `legacy` role map, reproducing pre-Pass-3 models exactly — backward compatibility without migration.
- Continuity (Pass 4) runs server-side in `check-continuity` via pure logic in `_shared/narrative/continuity.ts`, before extraction; history is append-only in `continuity_checks` — only the accepted final text ever reaches story memory.
- Manuscript audit uses pure `_shared/narrative/audit.ts`, caches manuscript/outline/memory hashes, writes only audit tables (owners change finding status/notes) — diagnosis never mutates prose or canon.
- Provider API keys are managed at app level (`/settings`), not per book — keys are per user.
- Live model prices are cached in `provider_pricing_cache` (signed-in read, service write) and refreshed from the gateway catalog when older than 24h via `_shared/ai/pricing.ts`; the registry prices are only a fallback.
- DeepSeek prices come from parsing its official pricing page at peak rates (no price API); Claude "adaptive" profile slots send thinking type adaptive (Opus 5.x rejects fixed budgets), "extended" sends a fixed budget.
- Book Ideas (`book-ideas`) always uses one OpenAI model and only suggests setups: it validates book type/audience/genre against the app catalog sent by the client and bounds sliders to the writer baseline ±2 server-side; it never writes books.
- Anthropic requests never send sampling params (temperature) — newer Claude models reject them.
- Book Ideas saves to `saved_book_ideas` (owner-only); `book-ideas` mode "light" returns only title/description/type/genre/audience, mode "details" builds the full setup for one idea at save time — AI credit is spent only on ideas the author keeps.
- Book Ideas entry points reuse the saved-idea library and the single Planning Studio creation path; importing an idea never consumes or deletes it, and setup replacement is unavailable after prose starts.
- Book approach selection is resolved through shared setup logic; persist nonfiction structure and await setup refresh before moving to master planning so UI and planner use the same selected option.
- Anthropic static system prompt uses ephemeral caching; below 1,024 tokens it skips silently. Benchmark: 2,146-token prefix cached, warm and cross-book reads confirmed.
- Progressive planning (Phase B) lives in `book_master_plans`, `book_progressive_plans` and `book_section_acceptances` (owner read-only, server writes); approved/ready plan content is frozen by DB triggers mirrored in `_shared/narrative/planning/lifecycle.ts` — plans never count as canon, only accepted + extracted prose does.
- Phase B safeguards (migration 0005): generation leases with monotonic fencing tokens (`assert_generation_fence` must run in the same transaction as any manuscript write), versioned immutable `narrative_exact_anchors`, and append-only `canon_reconciliation_logs` decided once by the signed-in owner via `decide_canon_reconciliation`; lease/anchor/discrepancy RPCs are service-role only, mirrored in pure `_shared/narrative/planning/safeguards.ts` and checked live by owner-only `phase-b-selftest` on `[2D-V` books — stale workers can never commit and contradictions are never silently accepted.
- Portraits use private owner paths/signed URLs and the shared OpenAI image service; demotion archives profiles without deleting links. Reuse uses a profile whitelist, never canon or knowledge; cast changes use setup_save.
- Conflict repairs stay versioned and fenced; display reconciliation never alters canon/history. Verbatim duplicates use pure `naturalnessMetrics.ts` and existing advisory findings, preserving statistical thresholds and acceptance.
- Forward autonomous repair runs only in progressive pre-acceptance, with at most two evidence-backed canon-compatible rounds after targeted repairs, cumulative draft-relative edit limits and full revalidation; successful repairs use resolved editorial history, never owner decision RPCs, so existing canon and fenced acceptance remain authoritative.
- Subdirectories have their own `AGENTS.md` (e.g. `supabase/functions/_shared/writers/`) — read it before changing files there.

- Blueprint cast checks use the shared adapter-aware example-role classifier across parsing, approval, writing gates and UI; instructional roles stay plan-local while named people and narrative books still require cast approval.
- All images go through `_shared/ai/openaiImage.ts` with one cheapest OpenAI model at low quality on both the user-key and gateway routes, and a failure never switches models — predictable image cost.
- Spoilers are judged as concepts by pure `planning/spoilerConcepts.ts`: keyword hit → skip if the chapter's own approved plan uses it → one AI judge against a ≥10-word concept sentence — bare word matches never reject plans.
